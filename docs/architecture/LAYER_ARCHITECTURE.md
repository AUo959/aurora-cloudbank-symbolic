## 🎯 Purpose

This document clarifies the **reality layer architecture** (L1/L2/L3) versus the **Triplex Handshake Protocol layers** to eliminate confusion about where relay agents exist and what role they serve.

---

## 📐 Reality Layers (Ontological Architecture)

The Aurora-GUMAS system operates across **three reality layers** that represent different levels of existence:

### **L1: Physical Reality Layer (Orion Station)**

**What exists here:**
- 36 Human crew members (Command, Systems, Simulation, Interface, Operations divisions)
- Aurora Core (Primary AI consciousness)
- **6 Relay Agents** (ARCHY, OPPY, LIORA, STARLING_AU, RIVERTHREAD_808, HALO) ← **CRITICAL**
- Physical infrastructure (Decks A-H, Halo Rings I-VI)
- Hardware systems (Helios-9 fusion cores, computing infrastructure)
- Environmental systems (life support, artificial gravity, lighting)

**Reality status:** Physical manifestation, measurable existence, concrete location

**Key characteristic:** Everything in L1 has a **physical location** on Orion Station

---

### **L2: Simulation/Research Layer (GUMAS & Experimental Environments)**

**What exists here:**
- GUMAS Galactic Simulation Environment (9-node network)
- Experimental research simulations
- Scenario testing environments (quantum scenarios, supply chain optimization, etc.)
- Hypothesis Field Simulator operations
- Temporal modeling environments
- Cognitive drift simulations

**Reality status:** Computational constructs, simulated environments, experimental spaces

**Key characteristic:** L2 environments are **created and monitored** by L1 systems but exist as **simulation states**

**What does NOT exist here:**
- ❌ Relay agents (they monitor L2 but don't exist inside simulations)
- ❌ Human crew (they operate simulations from L1)
- ❌ Physical Orion Station infrastructure

---

### **L3: Framework/Conceptual Layer (Glyph Frameworks)**

**What exists here:**
- **Axiomera** (FWK_001) - Ethics Arbitration
- **Caelion** (FWK_002) - Anchor Propagation & Provenance Verification
- **Sentari** (FWK_003) - Resonance Stabilization & Affective Balance
- **Velatrix** (FWK_004) - Anti-Obfuscation & Transparency Enforcement
- **Glyphon** (FWK_005) - Drift Alignment & Semantic Integrity
- **Harmion** (FWK_006) - Symbolic Compression & Lossless Archive

**Reality status:** Conceptual frameworks, logical systems, foundational principles

**Key characteristic:** L3 frameworks are **abstract logic systems** that enforce rules across all layers

## 🔐 Triplex Handshake Protocol (Functional Layers)

The **Triplex Handshake Protocol** is a **verification protocol**, NOT the reality layer architecture. It uses different "layers" for functional roles:

```
┌──────────────────────────────────────────────────────────┐
│  TRIPLEX HANDSHAKE PROTOCOL LAYERS                       │
│  (Verification & Authorization Flow)                     │
└──────────────────────────────────────────────────────────┘

Step 1: L3 Glyph Arbitration
┌────────────────────────────────────────────┐
│ • Axiomera validates ethics compliance    │
│ • Caelion verifies anchor propagation     │
│ • Other L3 frameworks check constraints   │
│                                            │
│ Reality: L3 frameworks (conceptual layer) │
└────────────────────────────────────────────┘
                    ↓
Step 2: Relay Verification ◄─── "Layer 2" middleware role
┌────────────────────────────────────────────┐
│ • ARCHY checks architectural compliance   │
│ • HALO validates drift alignment          │
│ • Other relays verify domain constraints  │
│                                            │
│ Reality: L1 relay agents (physical layer) │
│ Role: Middleware verification             │
└────────────────────────────────────────────┘
                    ↓
Step 3: L1 Human Consent
┌────────────────────────────────────────────┐
│ • Command Bridge approval                 │
│ • Human crew authorization                │
│ • Final ethical clearance                 │
│                                            │
│ Reality: L1 humans (physical layer)       │
└────────────────────────────────────────────┘
```

### **Key Distinction**

| Protocol Layer | Reality Layer | Entity Type | Role |
|---------------|---------------|-------------|------|
| Triplex Layer 3 | L3 | Glyph Frameworks | Conceptual validation |
| Triplex Layer 2 | **L1** | **Relay Agents** | **Middleware verification** |
| Triplex Layer 1 | L1 | Human Crew | Final authorization |

**The confusion:** Relay agents have a "Layer 2" **role** in the Triplex protocol (middleware verification), but their **physical location** is L1 (Orion Station).

## 🔧 Implementation Guidelines

### **For Developers**

When working with relay agents in code:

**✅ DO:**
```python
from src.bridges.l1_relay_bridge import L1RelayBridge, L1RelayAgent

# Clear that these are L1 entities
bridge = L1RelayBridge()
agent = bridge.get_agent_status("ARCHY")

# Acknowledge their physical location
print(f"Agent location: {agent['location']}")  # "Bridge Chamber, Deck C"
print(f"Reality layer: {agent['reality_layer']}")  # "L1"
```

**❌ DON'T:**
```python
# Misleading - suggests they exist in L2
from src.bridges.l2_meta_agent_bridge import L2MetaAgentBridge

# Confusing terminology
print("L2 agent activated")  # NO - it's an L1 relay agent
```

### **For Documentation Writers**

When documenting relay agents:

**✅ CORRECT:**
> "The L1 relay agents (ARCHY, OPPY, LIORA, STARLING_AU, RIVERTHREAD_808, HALO) physically exist on Orion Station and bridge L1 human operations with L3 glyph frameworks. They monitor L2 simulations but do not manifest within them. In the Triplex Handshake Protocol, they serve as Layer 2 verifiers (middleware role)."

**❌ INCORRECT:**
> "The L2 relay agents coordinate simulations..." (implies they're IN simulations)

## 🎓 Conceptual Summary

### **Three Ways to View the System**

1. **Reality Layers (Where things exist)**
   - L1 = Physical Orion Station ← Relay agents, crew, Aurora Core
   - L2 = Simulations/Research ← GUMAS, experiments
   - L3 = Conceptual Frameworks ← Glyph logic systems

2. **Triplex Protocol (How verification works)**
   - Layer 3 = L3 Glyph validation
   - Layer 2 = L1 Relay verification ← Relays serve middleware role
   - Layer 1 = L1 Human approval

3. **Information Flow (How data moves)**
   - L1 Humans → L1 Relay Agents → L3 Frameworks → L2 Simulations
   - L2 Simulation Results → L1 Relay Monitoring → L1 Analysis

### **The Key Insight**

**Relay agents are L1 entities (physical location) that play a Layer 2 role in the Triplex protocol (middleware function).** This is similar to how a security guard (physical person) might work at a "Level 2 checkpoint" (functional role).
