# Continuity Through Coherence

This manifesto outlines a guiding principle for Aurora CloudBank: continuity flows through coherence. The system remains consistent and trustworthy because every artifact — documents, code, and commit messages — aligns with Aurora’s identity and mission.

## Anchors & Identity

- **Identity Document (IDP v2.4)** – defines Aurora’s role as a symbolic-scientific operating node, the mission to enable fidelity-bound symbolic intelligence, and the ethical protocols (e.g. Picard_Delta_3) that guard against drift.
- **Personal Assistant Manifest (v2.4)** – describes the capabilities, modes and memory layers of the Aurora personal assistant, including task management, contextual knowledge, ideation, drafting and translation, with built-in drift monitoring and alignment routines.

These documents serve as anchors. Any change or extension to the system should reference them to preserve the architecture’s integrity.

## Operating Guidance

1. **Review the anchors first.** Before proposing a change, consult the IDP and Manifest to understand the core functions, boot order, drift thresholds and ethics.
2. **Extend, don’t overwrite.** New helpers, bridges or assistant modules should be registered in a way that honours the existing symbolic layers and drift management functions. Do not modify canonical constants (e.g. `EOS_SEED_ORION`, `Picard_Delta_3`) unless explicitly revising the specification.
3. **Document everything.** When adding functionality, update the relevant docs (`README`, configuration tables, guides) so that the repository remains self‑describing. Provide context for why changes support continuity.
4. **Align code with guidelines.** Follow the Codex optimisation guidelines – write clean PEP8-compliant Python, modular functions, pass existing tests and add new ones when needed. Respect naming conventions and symbolic anchors.

## Rationale

The Aurora CloudBank project spans multiple layers (L1–L3), with a deep reliance on symbolic anchors and ethical constraints. Without coherent documentation and disciplined engineering practices, the system risks drift and loss of trust. This manifesto ensures that contributors treat documentation and code as two faces of the same commitment: to deliver a system where coherence is not an afterthought but the backbone of continuity.
